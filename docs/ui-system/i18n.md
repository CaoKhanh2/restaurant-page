# 🌐 Internationalization (i18n) — FR / EN

**File:** `src/scripts/i18n.js` · init in `main.js → initI18n()` · lang init inline in `Layout.astro`

---

## How it works

1. **Dictionary** `translations = { fr: {...}, en: {...} }` — keys in the form `'section.field'`.
2. **Mark** elements to be translated with `data-i18n="key"`.
3. **`applyLang(lang)`** iterates over every `[data-i18n]`:
   - `input`/`textarea` → sets the `placeholder`; everything else → sets `textContent`.
   - **Skips missing keys** (`if (!t[key]) return`) → safe to add new `data-i18n` attributes without a translation yet (the original text is kept).
4. The language is stored in `localStorage('lang')`, defaulting to `fr`. Buttons have `data-lang-btn="fr|en"` to switch.
5. `Layout.astro` has an `<script is:inline>` that sets `<html lang>` **before paint** (prevents FR content flashing when EN is active).

---

## Adding a new translatable string

```html
<!-- markup: data-i18n on an element that contains ONLY text (no nested elements) -->
<h2 data-i18n="menu.formules.title">Nos Formules</h2>
```
```js
// src/scripts/i18n.js
fr: { 'menu.formules.title': 'Nos Formules', ... }
en: { 'menu.formules.title': 'Our Set Menus', ... }
```

> ⚠️ If the element has children (e.g. chip `🌶️ <span>Épicé</span>`), put `data-i18n` on the **child text span**, not on the parent (because `textContent` would wipe out the emoji/children).
